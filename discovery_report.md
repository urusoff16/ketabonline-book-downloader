# Исследование KetabOnline для книги 2722

Дата проверки: 17 июля 2026 года.

Исследована публичная страница:

`https://ketabonline.com/ar/books/2722/read?part=1&index=2049845`

## Обнаруженный способ получения текста

Основной арабский текст уже присутствует в серверном ответе внутри `window.__NUXT__.data[0].pageInView.content`. После гидратации Nuxt он превращается в обычный DOM. Управление браузером для штатного извлечения не требуется: загрузчик безопасно разбирает только литеральные параметры встроенного состояния и не исполняет JavaScript страницы. В итоговом DOM используются следующие устойчивые признаки:

- `.book-pages` — контейнер загруженных страниц;
- `.book-page[book-page-index]` — отдельная физическая страница;
- `.BookContentInner` и `.bookViewContent-inner` — контейнер текста страницы;
- `p.g-paragraph` — содержательный абзац;
- `span.g-square-brackets` — явно размеченный заголовок;
- `a.g-copy` — служебный элемент с метаданными `data-book-id`, `data-page-id`, `data-number`, `data-part-name`, `data-index`, `data-id` и `next-data-id`.

Серверное состояние одного запроса содержит одну выбранную физическую страницу. Клиент браузера дополнительно подгружает соседние страницы и может показать до трёх страниц в DOM, но загрузчик не полагается на это поведение. Арабские огласовки находятся непосредственно в Unicode-тексте `content` и сохраняются без OCR.

Отдельного документированного публичного JSON/API для текста при консервативной проверке не обнаружено. Поэтому рекомендуемый источник — встроенное серверное состояние Nuxt, а не управление браузером или недокументированные внутренние запросы.

## Значение URL-параметров

- `part` выбирает отображаемый том. Для книги обнаружено шесть томов.
- `page` — глобальный нулевой индекс физической страницы по всей книге. Он не сбрасывается между томами.
- Видимый номер страницы сбрасывается в каждом томе и берётся из `data-number`.
- `index` — один идентификатор или путь идентификаторов оглавления, например `2050090` или `2049998/2050012/2050013`. Это не последовательный номер текста.

Контрольные границы:

- том 1: `0..572` — 573 страницы;
- том 2: `573..1062` — 490 страниц;
- том 3: `1063..1705` — 643 страницы;
- том 4: `1706..2235` — 530 страниц;
- том 5: `2236..2727` — 492 страницы;
- том 6: `2728..3204` — 477 страниц.

Всего обнаружено 3205 физических страниц. В первом томе видимые номера идут от 2 до 574; в последнем последняя видимая страница — 478.

Инструмент не полагается на эти числа как на константы: он заново извлекает диапазоны из оглавления и ползунка каждого тома.

## Навигация и оглавление

Встроенное состояние содержит верхний уровень оглавления в `book.index`, а выбранную иерархию — в `pageInView.breadcrumb` и `pageInView.index`. После гидратации полное оглавление находится в ссылках `.BookSideMenuItem`. Ссылка содержит:

- название раздела в `rel` и видимом тексте;
- глобальный `page`;
- номер `part`;
- иерархические идентификаторы в соседних контейнерах `index-…`.

Следующая физическая страница определяется как следующий глобальный `page` внутри обнаруженных диапазонов. На границе тома меняется `part`, но глобальный индекс остаётся непрерывным. Внутри страницы `next-data-id` связывает абзацы и используется для дополнительной проверки.

## Официальные варианты

На странице есть ссылка на RIS-файл `https://s2.ketabonline.com/books/2722/2722.ris`, но это библиографические метаданные, а не полный текст. Сайт предлагает приложения и функции загрузки после регистрации, однако публичного полного текстового экспорта на исследованной странице не обнаружено.

## Ограничения и риски

- Разметка Nuxt и CSS-классы могут измениться; парсер проверяет обязательные метаданные и останавливается при неожиданной схеме.
- `index` отражает оглавление, а не каждую страницу; точная привязка хранится как список заголовков, путь оглавления и метаданные абзацев.
- Видимый номер страницы и глобальный индекс различаются.
- Одинаковый текст сам по себе не считается техническим дублем.
- Клиентская гидратация может переписывать адресную строку; загрузчик использует серверный HTML и собственную карту диапазонов.
- Проверка `robots.txt` во встроенном браузере была заблокирована клиентским фильтром. Инструмент не делает вывод о разрешении из отсутствия ответа: пользователь должен учитывать правила сайта и применимое право.
- Загрузчик не обходит вход, CAPTCHA, Cloudflare или ограничения доступа. Ответы 401, 403 и 404 считаются постоянными ошибками.
- По умолчанию запросы строго последовательны, между ними есть настраиваемая пауза.

## Рекомендуемый способ

1. Последовательно запросить по одной странице-наблюдению для каждого тома и построить диапазоны из метаданных частей и `input[type=range]`.
2. Скачивать глобальные страницы по возрастанию, извлекая `pageInView.content` из каждого серверного ответа без исполнения JavaScript.
3. После каждой страницы атомарно фиксировать запись в SQLite.
4. Сохранять `raw_text` без исправлений и отдельно `clean_text`, где удаляются только краевые и интерфейсные пробелы.
5. Проверять непрерывность индексов, абзацные ссылки, границы томов, Unicode и огласовки.
6. Экспортировать итоговые файлы только после успешной проверки.
